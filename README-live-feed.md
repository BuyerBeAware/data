# Daily beta map feed

County Discovery now publishes `feeds/beta.json` after BOTH St Johns and Flagler discovery jobs succeed. Schedule remains daily 10:30 UTC (5:30 a.m. EST / 6:30 a.m. EDT); GitHub can delay scheduled jobs. Manual Run workflow does the same work. The publisher does not depend on OpenAI or on the older Project Research workflow/API credential.

The publisher collects current St Johns GIS points with complete object-ID reconciliation and the existing description/road-side conflict gate. It uses the fresh Flagler discovery artifact, verifies configured GIS snapshots are complete, recomputes geometry interior points and county containment, and withholds unsupported directional claims. New locations are explicitly estimated application/project areas, not surveyed work footprints. News/community and records without geometry stay in review reports. Work dates and physical completion are not inferred from application dispositions, fiscal years, search snippets or population forecasts.

Stable identities are exact authority/application/feature identities; different phases/applications are not fuzzy-name merged. Conflicting incoming identities abort publication. Existing pin coordinates never move automatically, and absent source records never delete history. Coordinate changes are withheld in `feeds/latest-publication.json`. Source failure or invalid output fails the publish job and retains the last remote feed. The full candidate is validated before replacing the feed locally, and Git push must succeed to publish. Never force-push or overwrite unrelated changes.

`feeds/beta-seed.json` preserves the 346 accepted local beta rows. The feed remains `audience: bba-beta`, `reviewOnly: true`, `publicationAllowed: false`; it is intended for the explicitly configured BBA beta consumer. This is not a blanket promotion of the historical review data into the production `projects.json`. That production file/URL remain unchanged. The client retains the base pins, validates the entire incoming feed, uses a separate beta cache, rejects removal/movement/invalid sources, and retains saved data when offline. A client update is needed once to enable this endpoint; later data updates need no new build. Existing TestFlight clients do not acquire new loader code remotely.

Each publication has a schema version, UTC timestamp, project-content revision, supported counties and coverage notes. Full prior feed revisions live in version control under `feeds/history/`, making these normalized observations durable independently of evictable Actions caches/artifacts. They are not a claim to have complete permit history. Use git history for exact file recovery; regenerate/review a rollback candidate with a fresh timestamp rather than silently replaying an old feed against the client's monotonic timestamp/pin checks. Restore old content together with any deliberately reviewed coordinate policy change; never disable protection to force it through.

`latest-publication.json` records counts, withheld movement/side conflicts and source checks. Failed workflow notifications should be investigated; do not suppress them. GitHub's workflow-run page is the operational check. Scope remains configured official project layers and selected application registers, not every permit or municipality in Florida.

Run `python -m unittest discover -s scripts -p 'test_*.py'` before changing the publisher. Manual live generation: `python scripts/bba_publish_feed.py --artifacts research-output/county-discovery` after fresh successful county discovery. Publisher output is separate from production. Extend county source trust, county boundary checks and the app's explicit source policy together when adding jurisdictions.
